# MediSphere Telemedicine Service — Full API Documentation

**Base URL:** `http://localhost:8086`
**Auth:** All endpoints require `Authorization: Bearer <JWT>` from the auth service (`POST localhost:8083/api/v1/auth/login`)
**JWT subject (`sub`):** user's email
**JWT claim `role`:** `PATIENT` | `DOCTOR` | `ADMIN`

---

## Service Dependencies

| Service | Port | Used For |
|---|---|---|
| Auth Service | 8083 | JWT token issuance & validation |
| Patient Service | 8084 | Validating patient IDs (P001 format) |
| Doctor Service | 8085 | Validating & fetching doctor records |
| Telemedicine Service | 8086 | This service |

---

## Key Identifiers

| Identifier | Format | Where it comes from |
|---|---|---|
| `patientId` | `P001`, `P002`, … | Patient service (`GET /patient/api/v1/getAllPatientForAdmin`) |
| `doctorId` | `UD102616`, … | Doctor service (`GET /doctor/api/v1/getAllDoctors`) |
| `sessionId` | UUID string | Generated by telemedicine on session creation |
| `prescriptionId` | UUID string | Generated by telemedicine on prescription creation |

---

## Session Lifecycle

```
[DOCTOR creates]   → SCHEDULED
[PATIENT requests] → PENDING_APPROVAL → (doctor accepts) → SCHEDULED
                                      → (doctor rejects) → CANCELLED

SCHEDULED → (start) → ACTIVE → (end) → COMPLETED → (prescription can be issued)
Any non-COMPLETED/CANCELLED → (cancel) → CANCELLED
```

## Doctor Endpoints

### GET /api/doctors
Get all doctors from the doctor service.

- **Auth:** PATIENT, DOCTOR, ADMIN
- **Response 200:**
```json
[
  {
    "doctorId": "UD102616",
    "firstName": "John",
    "lastName": "Smith",
    "specialty": "Cardiology",
    "status": "ACTIVE"
  }
]
```

---

### GET /api/doctors/{doctorId}
Get a single doctor by their service ID.

- **Auth:** PATIENT, DOCTOR, ADMIN
- **Path param:** `doctorId` — e.g. `UD102616`
- **Response 200:** Single doctor object from doctor service

## Session Endpoints

### POST /api/sessions
Doctor creates a session for a patient. Session is immediately `SCHEDULED`.

- **Auth:** DOCTOR only
- **Request body:**
```json
{
  "patientId": "P001",
  "doctorId": "UD102616",
  "scheduledAt": "2026-04-20T10:00:00"
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `patientId` | String | Yes | Must exist in patient service |
| `doctorId` | String | Yes | Must exist in doctor service |
| `scheduledAt` | LocalDateTime | Yes | ISO-8601 format |

- **Response 201:**
```json
{
  "sessionId": "3f2a1b...",
  "patientId": "P001",
  "doctorId": "UD102616",
  "roomName": "medisphere-teleabc123def456",
  "roomUrl": "https://meet.jit.si/medisphere-teleabc123def456",
  "status": "SCHEDULED",
  "scheduledAt": "2026-04-20T10:00:00",
  "startedAt": null,
  "endedAt": null,
  "durationMinutes": null,
  "notes": null,
  "requestReason": null,
  "createDate": "2026-04-17T10:00:00",
  "modifiedDate": "2026-04-17T10:00:00",
  "jitsiToken": null
}
```

---

### POST /api/sessions/request
Patient requests a session with a doctor. Goes into `PENDING_APPROVAL` — the doctor must accept before it becomes `SCHEDULED`.

- **Auth:** PATIENT only
- **Request body:**
```json
{
  "patientId": "P001",
  "doctorId": "UD102616",
  "preferredAt": "2026-04-20T10:00:00",
  "reason": "Headache for 3 days"
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `patientId` | String | Yes | Must exist in patient service |
| `doctorId` | String | Yes | Must exist in doctor service |
| `preferredAt` | LocalDateTime | Yes | Patient's preferred time |
| `reason` | String | No | Patient's stated reason |

- **Response 201:** Session object with `status: PENDING_APPROVAL`

---

### GET /api/sessions/{sessionId}
Get a session by ID. Returns a role-aware Jitsi token — moderator token for doctors, participant token for patients.

- **Auth:** PATIENT, DOCTOR, ADMIN
- **Path param:** `sessionId` — UUID
- **Response 200:** Full session object including `jitsiToken` for use in the Jitsi video room

---

### GET /api/sessions/patient/{patientId}
Get all sessions for a patient.

- **Auth:** PATIENT, ADMIN
- **Path param:** `patientId` — e.g. `P001`
- **Response 200:** Array of session objects (no `jitsiToken`)

---

### GET /api/sessions/doctor/{doctorId}
Get all sessions for a doctor.

- **Auth:** DOCTOR, ADMIN
- **Path param:** `doctorId` — e.g. `UD102616`
- **Response 200:** Array of session objects (no `jitsiToken`)

---

### GET /api/sessions/doctor/{doctorId}/pending
Get all `PENDING_APPROVAL` sessions waiting for a specific doctor's decision.

- **Auth:** DOCTOR, ADMIN
- **Path param:** `doctorId` — e.g. `UD102616`
- **Response 200:** Array of session objects with `status: PENDING_APPROVAL`

---

### PUT /api/sessions/{sessionId}/accept
Doctor accepts a `PENDING_APPROVAL` session → moves to `SCHEDULED`.

- **Auth:** DOCTOR only
- **Path param:** `sessionId`
- **Body:** none
- **Response 200:** Session object with `status: SCHEDULED`
- **Errors:**
  - `400` — session is not in `PENDING_APPROVAL` state

---

### PUT /api/sessions/{sessionId}/reject
Doctor rejects a `PENDING_APPROVAL` session → moves to `CANCELLED`.

- **Auth:** DOCTOR only
- **Path param:** `sessionId`
- **Body:** none
- **Response 200:** Session object with `status: CANCELLED`
- **Errors:**
  - `400` — session is not in `PENDING_APPROVAL` state

---

### PUT /api/sessions/{sessionId}/start
Mark a session as `ACTIVE` when either party joins the video room. Records `startedAt` timestamp.

- **Auth:** PATIENT, DOCTOR
- **Path param:** `sessionId`
- **Body:** none
- **Response 200:** Session object with `status: ACTIVE`, `startedAt` populated
- **Errors:**
  - `400` — session is `PENDING_APPROVAL` (not accepted yet), `CANCELLED`, or already `COMPLETED`

---

### PUT /api/sessions/{sessionId}/end
Doctor ends the session → moves to `COMPLETED`. Records `endedAt` and calculates `durationMinutes`. Sends a completion notification (non-blocking).

- **Auth:** DOCTOR only
- **Path param:** `sessionId`
- **Request body** (optional):
```json
{
  "notes": "Patient presenting with viral fever. Advised rest."
}
```
- **Response 200:** Session object with `status: COMPLETED`, `endedAt` and `durationMinutes` populated
- **Errors:**
  - `400` — session is `CANCELLED`

---

### PUT /api/sessions/{sessionId}/cancel
Cancel a session.

- **Auth:** PATIENT, DOCTOR, ADMIN
- **Path param:** `sessionId`
- **Body:** none
- **Response 200:** Session object with `status: CANCELLED`
- **Errors:**
  - `400` — session is already `CANCELLED` or `COMPLETED`

## Prescription Endpoints

> Prescriptions can only be issued for sessions with `status: COMPLETED`. One prescription per session.

### POST /api/prescriptions
Doctor issues a prescription after a completed session.

- **Auth:** DOCTOR only
- **Request body:**
```json
{
  "sessionId": "3f2a1b...",
  "diagnosis": "Viral fever",
  "medications": [
    {
      "name": "Paracetamol",
      "dosage": "500mg",
      "frequency": "Every 6 hours",
      "duration": "5 days"
    }
  ],
  "instructions": "Take with food. Rest and drink plenty of water."
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `sessionId` | String | Yes | Session must be `COMPLETED` |
| `diagnosis` | String | Yes | |
| `medications` | Array | Yes | At least one item required |
| `instructions` | String | No | |

- **Response 201:**
```json
{
  "prescriptionId": "a1b2c3...",
  "sessionId": "3f2a1b...",
  "patientId": "P001",
  "doctorId": "UD102616",
  "diagnosis": "Viral fever",
  "medications": [
    {
      "name": "Paracetamol",
      "dosage": "500mg",
      "frequency": "Every 6 hours",
      "duration": "5 days"
    }
  ],
  "instructions": "Take with food.",
  "issuedAt": "2026-04-17T11:30:00",
  "createDate": "2026-04-17T11:30:00",
  "modifiedDate": "2026-04-17T11:30:00"
}
```
- **Errors:**
  - `400` — session not completed, patient/doctor not found in their services, or prescription already exists for this session

- **Auth:** DOCTOR only
- **Request body:**

- **Auth:** DOCTOR, ADMIN

## Common Error Responses

| Status | Cause |
|---|---|
| `401 Unauthorized` | Missing, expired, or invalid JWT token |
| `403 Forbidden` | Valid token but wrong role for this endpoint |
| `404 Not Found` | Session or prescription ID does not exist |
| `400 Bad Request` | Validation failure or business rule violation (wrong status, duplicate prescription, unknown patient/doctor) |
| `500 Internal Server Error` | Unexpected server error — check service logs |

## Full Test Flow (Postman Order)

```
1.  POST   localhost:8083/api/v1/auth/login                          → get PATIENT_TOKEN
2.  POST   localhost:8083/api/v1/auth/login                          → get DOCTOR_TOKEN
3.  GET    localhost:8084/patient/api/v1/getAllPatientForAdmin        → find PATIENT_ID (e.g. P001)
4.  GET    localhost:8086/api/doctors                                 → find DOCTOR_ID (e.g. UD102616)

    --- Doctor-created flow ---
5.  POST   localhost:8086/api/sessions                                → DOCTOR creates → SESSION_ID
6.  PUT    localhost:8086/api/sessions/{SESSION_ID}/start             → status: ACTIVE
7.  PUT    localhost:8086/api/sessions/{SESSION_ID}/end               → status: COMPLETED
8.  POST   localhost:8086/api/prescriptions                           → issue prescription → PRESCRIPTION_ID
9.  GET    localhost:8086/api/prescriptions/{PRESCRIPTION_ID}         → view prescription

    --- Patient-request flow ---
10. POST   localhost:8086/api/sessions/request                        → PATIENT requests → SESSION_ID
11. GET    localhost:8086/api/sessions/doctor/{DOCTOR_ID}/pending     → DOCTOR sees pending requests
12. PUT    localhost:8086/api/sessions/{SESSION_ID}/accept            → status: SCHEDULED
13. PUT    localhost:8086/api/sessions/{SESSION_ID}/start             → status: ACTIVE
14. PUT    localhost:8086/api/sessions/{SESSION_ID}/end               → status: COMPLETED
15. POST   localhost:8086/api/prescriptions                           → issue prescription
```
